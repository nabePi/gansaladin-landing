# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Next.js 16 (App Router) marketing site for **Yayasan Saladin Peradaban Berilmu / GenSa**, an Indonesian Islamic education/da'wah foundation. Five static pages, all content hardcoded in TSX (no CMS, no database, no API routes). This is intentional, not a gap — **do not add a database, backend persistence, or API route without the project owner's explicit go-ahead first**, even if a requested feature seems to need one (e.g. actually persisting form submissions). Say what the feature would require and ask before building it.

Git remote: `https://github.com/nabePi/gansaladin-landing` (branch `main`).

## Commands

```bash
npm run dev      # start dev server (Turbopack) on http://localhost:3000
npm run build    # production build (Turbopack)
npm run start    # run the production build
npm run lint     # eslint (flat config: eslint-config-next core-web-vitals + typescript)
npx tsc --noEmit # typecheck (no separate typecheck script defined)
```

There is no test suite/framework configured in this repo (no test runner in `package.json`).

## Architecture

- **Routing**: file-based App Router pages under `src/app/` — `/` (page.tsx), `/tentang`, `/program`, `/bergabung`, `/dukung`. Each route's page is a server component; interactive pieces are split into a co-located `"use client"` component (e.g. `program/program-tabs.tsx`, `bergabung/join-form.tsx`, `dukung/donation-panel.tsx`) and imported into the page. `Navbar` is also a client component (scroll-position + mobile-menu state); `Footer` is a shared server component. Both are rendered once in `src/app/layout.tsx` around `{children}`.
- **Content**: each page's copy/data lives as plain arrays/objects at the top of its `page.tsx` (or passed into its client sub-component) — there is no external content source. Edit the TSX directly to change copy.
- **Styling**: Tailwind CSS v4, CSS-first config in `src/app/globals.css` (no `tailwind.config.*`). Brand colors are defined as CSS variables in `:root` and re-exposed via `@theme inline` (e.g. `--color-maroon`, `--color-beige`, `--color-gold`, `--color-ink`, each with `-light`/`-mid`/`-dark` variants) — use them as Tailwind utilities like `bg-maroon`, `text-ink-mid`. Fonts (Playfair Display for `font-serif`, DM Sans for `font-sans`) are loaded via `next/font/google` in `layout.tsx` and mapped to Tailwind's `--font-serif`/`--font-sans` tokens in the same `@theme inline` block. Custom keyframe animations (e.g. `animate-scroll-chevron`) are also defined in `globals.css` via `--animate-*` theme tokens + `@keyframes`, with `prefers-reduced-motion` overrides.
- **Icons**: all SVG icons (including brand glyphs like WhatsApp/Instagram) are hand-authored components in `src/components/icons.tsx` — no icon package dependency. Emojis are intentionally avoided in UI in favor of these SVGs.
- **Shared UI primitives**: `src/components/` holds `navbar.tsx`, `footer.tsx`, `page-header.tsx` (hero/header band used by every non-home page), `section-label.tsx` (small eyebrow label), `geom-ornament.tsx` (decorative SVG motif), and `icons.tsx`.
- **Images**: static assets live in `public/images/`. Favicon uses the Next.js file convention (`src/app/icon.png` + `src/app/apple-icon.png`) rather than a `favicon.ico`/metadata `icons` field — both were generated by cropping just the icon mark out of the full logo lockup (see `public/images/logo-color.png` / `logo-white.png`, which are the full logo lockups already trimmed of excess transparent margin).
- **Metadata**: `src/app/layout.tsx` exports `metadata` (title/description/applicationName) and a separate `viewport` export (`themeColor`) — in the App Router these are two distinct exports, not one object. Per-page `metadata` (title) is set in each `page.tsx`.
- **Path alias**: `@/*` → `src/*` (see `tsconfig.json`).
- **`next.config.ts`**: sets `turbopack.root` explicitly to silence a false-positive root-inference warning caused by an unrelated `package-lock.json` in the parent home directory — keep this if the warning reappears.
- **`refernesi/`**: the original static HTML/React-in-a-single-file design reference this site was ported from (colors, copy, layout, component structure). It is not part of the Next.js app, is excluded from ESLint (`eslint.config.mjs`), and should not be built or imported from — it's kept only as a design/content reference.

## Deployment

Deployed via **Dokploy** using the **Nixpacks** builder. `nixpacks.toml` at the repo root defines the build plan (`npm ci` → `npm run build` → `npm run start`, caching `.next/cache`); `package.json` pins `engines.node >= 20.9.0` so Nixpacks selects a compatible Node version. `next start` already binds to `0.0.0.0` and reads `PORT` from the environment, so no extra host/port config is needed — Dokploy injects `PORT` automatically.

`ONBOARDING.md` is a separate, Indonesian-language guide for a **non-technical collaborator** pairing with Claude on this project. It instructs Claude to handle git (clone/pull/commit/push) and environment setup (node/npm) autonomously, including committing and pushing without asking for confirmation first. ## Conventions observed in this codebase

- No comments unless explaining a non-obvious constraint; components are typed with inline prop types rather than separate `interface`/`type` declarations for simple components.
- Accessibility: interactive icon-only controls get `aria-label`; decorative SVGs get `aria-hidden="true"`; progress bars use `role="progressbar"` with `aria-valuenow/min/max`.
- External links (WhatsApp, Instagram) use `target="_blank" rel="noopener noreferrer"`; `mailto:` links do not.
